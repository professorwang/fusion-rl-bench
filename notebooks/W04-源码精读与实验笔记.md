## 一、Gym-TORAX 架构精读（代码事实，非文档转述）

```
BaseEnv (gym.Env, ABC)                    envs/base_env.py (572 行)
├── 子类钩子：_define_observation_space / _define_action_space / _get_torax_config / _compute_reward
├── step() 流程（base_env.py:310）：
│   1. torax_app.update_config(action)     ← 动作写入 TORAX 配置（含限幅/爬坡率裁剪，info["action_clipped"]）
│   2. torax_app.run()                     ← 物理步进一个 delta_t_a
│   3. torax_app.get_state_data()          ← ★ StateHistory.simulation_output_to_xr() 每步强制执行
│   4. observation_handler.extract_state_observation(DataTree) → (state, observation)
│   5. _compute_reward(state, next_state, action)；失败/观测越界 → reward=-1000 且终止
├── ToraxApp（torax_wrapper/torax_app.py，471 行）
│   └── run()：step_fn.jitted_fixed_time_step(delta_t_a, sim_state, sim_output)
│       —— JAX jit 编译的固定步长推进；每个 action 步内可含多个物理子步
├── Observation / AllObservation（observation_handler.py）
│   └── 从 xarray DataTree 提取变量 → spaces.Dict；AllObservation 支持 exclude 列表
├── Action / ActionHandler（action_handler.py，978 行）
│   └── 动作带 min/max 边界 + ramp rate 约束，超界自动 clip
└── rewards.py：现成物理量 getter（Q 增益、β_N、τ_E、H98、q 剖面、q95…）← 奖励函数零件库
```

**关键设计评价**：
- 优点：钩子结构清晰、动作裁剪与失败惩罚内置、reward 零件库好用；
- 缺点：**观测链路强制走 xarray**（`get_state_data()` 无论 `store_history` 与否都调 `simulation_output_to_xr()`），训练场景浪费；
- 缺点：控制对象是 scenario 级参数（Ip/NBI/ECRH），无线圈级控制（我们已用 FreeGSNKE 环境补位）。

## 二、性能实验（scripts/bench_step.py，30 步实测）

| 模块 | 合计 | 均值/步 | 占比 |
|---|---|---|---|
| 物理步进 torax_app.run | 37.32 s | 1244 ms | 80.6% |
| xarray 转换 get_state_data | 4.89 s | 158 ms | 10.5% |
| 观测提取 extract | 0.10 s | 3 ms | 0.2% |

（总 46.3 s/30 步。注：占比随工况变化——W03 完整 150 步 profile 中 xarray 占 25%；早期电流爬升段物理步进更慢摊薄了占比。）

**优化结论**：RL 训练时应绕过 xarray，直接从 `torax_app.current_sim_state` / `current_sim_output`（TORAX 原生对象）取观测变量——预计省 10–25% step 时间。实现方式：自定义 Observation 子类读原生对象，或 monkey-patch `get_state_data`。列为 fusion-rl-bench v0.2 任务。

## 三、随机策略下界（scripts/random_stats.py，3 episode）

- 动作空间：`Ip ∈ [1e3, 1.5e7]A`，`NBI ∈ [0, 3.3e7]W + r/w`，`ECRH ∈ [0, 2e7]W + r/w`
- 结果：3 个 episode 全部存活满 150 步（150s），累计奖励均 ≈ 3.1
- **解读**：TORAX 1.5D 输运模型不含 MHD 不稳定性/破裂物理，随机乱调也不会"炸等离子体"——**TORAX 环境无法训练破裂规避类控制器**，这再次印证线圈级 FreeGSNKE 环境 + 后续接入不稳定性判据的必要性。RL baseline 下界记录：reward ≈ 3.1（随机）。

## 四、fusion-rl-bench v0.1 冒烟通过（envs/freegsnke_shape_env.py）

- MAST-U 装置构建 + 基线平衡收敛（21 次牛顿迭代到 1e-6），reset 113.6s（一次性）
- 随机动作 3 步均收敛（5–6 次迭代/步，**0.35–0.48 s/步**）；LCFS 偏差奖励 0.0136→0.0025 m 单调改善（随机漂移下的合理量级）
- 观测维度 41（16 LCFS 点 ×2 + 2 psi + 7 线圈电流），动作 7 线圈 ΔI ∈ [-1,1]（±5%/步）
- **0.4s/步 的求解速度对 RL 可用**（1 万步 ≈ 1.1 小时 CPU），后续可加并行走数
